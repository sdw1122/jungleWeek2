# Farmda 백엔드 모듈 개발 계획

## 요약

- Flask를 단일 백엔드로 사용하고 PostgreSQL·SQLAlchemy·Flask-Migrate를 연결한다.
- 이메일/비밀번호와 Google OAuth, 식물 성장, OpenAI 채팅, 일기·미디어, 회원 간 선물, 공개 방명록을 모두 구현한다.
- 공통 모델·API 계약을 먼저 확정한 뒤 기능 모듈을 병렬 개발하고, 마지막에 기존 프론트의 로컬 상태를 API 기반으로 교체한다.
- Express Mock API는 Flask API 전환 완료 후 제거한다.

## 핵심 구현

### 공통 기반과 데이터

- Alembic 마이그레이션을 스키마의 기준으로 삼고 초기 SQL도 동일하게 유지한다.
- `plant_species`에 이름, 카테고리, 설명, 물·습도·토양·광량·기타 관리법을 추가해 현재 도감 데이터를 DB로 이전한다.
- `care_logs.action_type`에 `IGNORE`를 추가하고, AI 일기 중복 방지를 위해 `diary_date`와 식물별 일일 AI 일기 유일 제약을 추가한다.
- JSON은 camelCase, 시간은 UTC ISO 8601, 오류는 `{error: {code, message, fields}}` 형식으로 통일한다.
- 세션 쿠키는 HttpOnly·SameSite=Lax를 사용하고 모든 변경 요청에 CSRF 토큰을 요구한다.
- 돌봄과 채팅 요청은 `clientRequestId` UUID를 받아 중복 요청이 성장 수치를 두 번 반영하지 않게 한다.

### 인증 모듈

- `POST /api/v1/auth/signup`, `/login`, `/logout`, `GET /me`, `GET /csrf`를 제공한다.
- Google OAuth 시작·콜백 엔드포인트를 Authlib로 구현한다.
- 이메일은 소문자로 정규화하고 비밀번호는 Werkzeug 해시, 길이 8~128자로 검증한다.
- Google 이메일과 기존 로컬 계정이 충돌하면 자동 연결하지 않고 `ACCOUNT_EXISTS_USE_PASSWORD`로 차단한다.
- 로그인·회원가입·OAuth 콜백에 속도 제한을 적용하고 탈퇴는 삭제 대신 `WITHDRAWN` 상태로 처리한다.

### 식물·성장 모듈

- 식물 종류 검색·상세, 내 식물 목록·생성·상태 조회 API를 제공한다.
- 현재 소유자만 비공개 식물 조회, 돌봄, 채팅, 일기 작성, 선물을 수행할 수 있다.
- 성장 규칙을 하나의 서비스에서 관리한다.
  - `WATER`, `SUNLIGHT`, `PET`, `PRAISE`: 성장 `+5`, 긍정 `+5`
  - `IGNORE`: 성장 `+5`, 부정 `+5`
  - 긍정 채팅: 성장 `+1`, 긍정 `+1`
  - 부정 채팅: 성장 `+1`, 부정 `+1`
  - 중립 채팅: 성장 `+1`, 성향 변화 없음
- 성장도는 100에서 제한하고 100 이후 돌봄·채팅은 `PLANT_FULLY_GROWN`으로 거절한다.
- 식물 갱신과 `care_logs` 생성은 행 잠금이 포함된 단일 트랜잭션으로 처리한다.

### AI 채팅·일기 모듈

- OpenAI 공식 Python SDK와 Responses API를 사용하고 기본 모델은 `gpt-5.6-luna`로 설정한다. 모델은 환경변수로 교체 가능하게 한다. [OpenAI 공식 모델 지침](https://developers.openai.com/api/docs/guides/latest-model)
- 채팅 출력은 JSON Schema로 `reply`, `sentiment`만 생성하고 실제 성장 변화량은 서버 규칙으로 계산한다.
- 최근 메시지 20개와 식물 이름·단계·성향을 문맥으로 전달하며 사용자 메시지는 500자로 제한한다.
- API 키는 서버 환경변수에만 저장하고 `store=false`, 사용자 ID의 비식별 해시를 안전 식별자로 사용한다.
- 10초 타임아웃과 일시 오류 1회 재시도를 적용한다. 최종 실패 시 메시지와 성장도를 저장하지 않고 502를 반환한다.
- AI 일기는 사용자가 요청할 때 당일 돌봄·대화 기록을 요약해 생성하고 `source_type=AI`와 성장 상태 스냅샷을 저장한다.
- 사용자 일기와 AI 일기 모두 수정 가능하지만 AI 일기를 수정해도 `source_type`은 유지한다.

### 미디어·선물·방명록 모듈

- 일기 미디어는 multipart 업로드로 받고 이미지 10MB, 영상 50MB까지 MIME과 확장자를 함께 검증한다.
- 파일은 Git 외부의 설정 가능한 업로드 디렉터리에 UUID 이름으로 저장한다.
- 미디어 조회 라우트는 공개 일기 또는 현재 소유자 권한을 확인하고 영상은 조건부 전송을 지원한다.
- 선물은 성장도 100인 식물만 기존 활성 회원의 이메일로 보낼 수 있다.
- 생성 시 `SENT/GIFT_READY`, 수락 시 기존 소유권 종료·신규 소유권 생성·`ACCEPTED/GIFTED` 변경을 하나의 트랜잭션으로 처리한다.
- 수신 전에는 발신자가 취소할 수 있으며 등록코드와 외부 이메일 발송은 이번 버전에서 사용하지 않는다.
- 공개 일기와 방명록은 비로그인 조회를 허용한다. 방명록 작성은 로그인 사용자, 수정은 작성자, 삭제는 작성자 또는 현재 식물 소유자에게 허용한다.

## 공개 API

- 인증: `/api/v1/auth/*`
- 식물 종류: `GET /api/v1/species`, `GET /api/v1/species/:id`
- 내 식물: `GET/POST /api/v1/plants`, `GET /api/v1/plants/:id`
- 돌봄: `POST /api/v1/plants/:id/care`
- 채팅: 식물별 세션 생성·목록, 세션별 메시지 조회·전송·종료
- 일기: 식물별 목록·작성, AI 일기 생성, 상세 수정·삭제
- 미디어: 일기별 업로드·삭제, 권한 기반 파일 조회
- 선물: 생성, 보낸/받은 목록, 수락, 취소
- 공개 콘텐츠: 공개 일기 목록·상세, 식물별 방명록 CRUD

프론트는 로그인 성공 후 세션 쿠키를 사용하고, `localStorage`에는 식물 상태를 저장하지 않는다. 기존 식물 선택·대시보드·일기·도감 화면은 위 API 응답으로 갱신한다.

## 병렬 개발과 통합 순서

1. 공통 팀이 모델, 마이그레이션, 인증 미들웨어, 오류 형식, 성장 서비스와 API 계약을 먼저 고정한다.
2. 인증, 식물·돌봄, AI 채팅, 일기·미디어, 선물·방명록 모듈을 계약 기준으로 병렬 구현한다.
3. 각 모듈은 외부 서비스와 인접 모듈을 Mock 처리해 독립적으로 테스트한다.
4. 통합 단계에서 실제 PostgreSQL, Google OAuth 테스트 설정, OpenAI 테스트 키를 연결한다.
5. 프론트를 Flask API로 전환한 뒤 Express `src/`와 Node 실행 설정을 제거한다.

## 테스트 및 완료 기준

- 성장 경계값 0·4·5·19·20·39·40·69·70·100과 긍정/부정 동률을 단위 테스트한다.
- 회원가입 중복, 비밀번호 실패, Google 이메일 충돌, CSRF 및 세션 만료를 검증한다.
- 비소유자의 돌봄·채팅·비공개 일기 접근이 403인지 확인한다.
- 중복 `clientRequestId`와 동시 돌봄 요청에서도 성장 수치와 로그가 한 번만 반영되는지 검증한다.
- OpenAI 성공·잘못된 구조화 응답·타임아웃·재시도 실패 시 DB 정합성을 검증한다.
- AI 일기 일일 중복, 미디어 크기·MIME·경로 조작, 비공개 미디어 접근을 검증한다.
- 선물 수락 동시 요청, 취소 후 수락, 자기 자신에게 선물, 미완성 식물 선물을 검증한다.
- 신규 DB에서 마이그레이션과 초기 SQL이 모두 동일한 스키마를 생성하는지 확인한다.
- 로그인→식물 생성→돌봄→채팅→AI 일기→성장 완료→선물 수락→방명록 작성 흐름을 E2E 테스트한다.

## 확정된 기본값

- 서비스 기준 날짜: Asia/Seoul, DB 저장 시간: UTC
- 인증: 서버 세션, 이메일+Google OAuth
- Google 중복 이메일: 자동 연결 없이 차단
- AI: OpenAI Responses API, 기본 모델 `gpt-5.6-luna`
- AI 일기: 사용자 요청 시 생성, 자동 스케줄러 없음
- 선물: 기존 회원에게만 전달, 등록코드 미사용
- 미디어: 로컬 저장, 이미지 10MB·영상 50MB
- 공개 일기·방명록: 비로그인 조회 허용
